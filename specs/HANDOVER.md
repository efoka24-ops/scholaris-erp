# SCHOLARIS : résumé technique et passation

Date : 2026-10-13. Public : un ingénieur ou un agent qui reprend le projet sans avoir suivi son historique. Première mission prévue : analyser et préparer l'application **École primaire** (voir §11).

## 1. Ce qu'est le produit
Plateforme ERP scolaire multi-clients (SaaS) pour le Cameroun. Un **socle** commun (comptes, organisation, personnes, facturation, messagerie, documents, emplois du temps, présences, évaluation, personnel, tableaux de bord, conformité) et des **applications** par cible : Supérieur/IPES (en cours), Secondaire, Primaire, Maternelle (à faire). Une **plateforme** au-dessus des clients gère le catalogue d'applications, les demandes d'accès, les essais (90 jours) et les abonnements.

Cahiers des charges : plateforme (`specs/001-socle-plateforme/spec.md`), IPES (`specs/002-application-ipes/cdc-ipes.md` et `cdc-ipes-complement.md`, PDF complet fourni). **Il n'existe aucun cahier des charges pour le primaire, le secondaire ni la maternelle.**

## 2. Contraintes d'hébergement (elles gouvernent tout)
- Hébergement mutualisé **Camoo** : PHP **8.1** uniquement, MySQL 8.0.46 joignable seulement depuis le serveur, `.htaccess` avec **mod_rewrite seulement** (toute directive Options/FilesMatch/Require provoque une 500), pas de SSH, pas de Redis, pas de Docker, pas de Node en production.
- Terminal du serveur (CSHIELD) : seulement `artisan`, `composer`, `git`, `ls`, `cd`, `cat`, `rm`, `unzip`. Il **coupe les arguments aux espaces et garde les guillemets** : les commandes console acceptent des noms en plusieurs mots et retirent les guillemets parasites.
- Déploiement par **FTP** (limité en débit : rafales bloquées temporairement). `scripts/deploy-ftp.ps1` fait des essais répétés avec attentes.
- Le site est en **HTTP** (pas de certificat pour l'instant). Le HSTS n'est envoyé qu'en HTTPS.
- Décision d'architecture (ADR-0001, `specs/001-socle-plateforme/adr-0001-php81-sans-framework.md`) : **PHP 8.1 sans framework**, standards PSR. Les documents de conception parlent encore de Laravel/PHP 8.4/PostgreSQL : c'est un **écart voulu**, tout est réalisé en PHP 8.1 sans framework, MySQL 8, Dompdf.

## 3. Architecture du code
```
src/Core/                 noyau : Kernel, Http (pipeline PSR-15, RouteRegistry, ListQuery, ExportsList, XlsxWriter),
                          Tenancy, Security, Database (Migrator), Console, Container, RateLimit, Idempotency, Support/Ulid
src/Modules/Socle/<Module>/   Contracts, Domain, Application, Http, Infrastructure, Console,
                              Database/Migrations, routes.php, definitions.php
src/Modules/Apps/<App>/       applications (Higher = IPES ; Primary, Nursery, Secondary = vides)
database/migrations/      migrations partagées (noyau, rôles, permissions, modèles de messages de plateforme)
config/  public/  web/  scripts/  specs/  tests/
```
- **Kernel** : pipeline ErrorHandler, SecurityHeaders, Cors, Locale, RouteResolver, Authenticate, RateLimit, ResolveEstablishment, Idempotency, ControllerInvoker. Erreurs RFC 9457 avec `trace_id`. API sous `/api/v1`. En-tête `X-Establishment-Id`. `Idempotency-Key` sur les routes de paiement et d'émission.
- **Chargement automatique** : le Kernel charge `src/Modules/*/*/routes.php` et `definitions.php`, et le Migrator les migrations `database/migrations/*.sql`, `src/Modules/*/*/Database/Migrations/*.sql` et `src/Modules/Apps/*/*/Database/Migrations/*.sql`. **`definitions.php` est fusionné par `array_merge`** : une liaison unique posée par deux modules s'écrase ; pour une extension par application, on utilise des **clés de liste du conteneur** (`<prefixe>.<application>`), découvertes par `getKnownEntryNames()`.
- **Règle d'architecture** (`tests/Architecture/StandardsTest`) : une application n'utilise **que les `Contracts/`** du socle ; le noyau ne dépend pas des modules ; `NoForeignTableReadTest` interdit à un module de lire les tables `users`/`people` d'un autre module. Les contrats d'écriture et les points d'extension du socle sont ce qui permet de bâtir une application.
- **Multi-tenant** : `tenant_id` sur toute table, `establishment_id` pour les tables d'établissement ; `TenantTable` impose le filtre ; un identifiant d'un autre client donne 404.
- **SQL portable MySQL 8 + SQLite** (les tests tournent sur SQLite) : ULID `CHAR(26)` via `Scholaris\Core\Support\Ulid` (classe maison, pas de dépendance Symfony), dates ISO en `VARCHAR(32)`, montants entiers en XAF, pas d'AUTO_INCREMENT/ENGINE/clé étrangère, une colonne par `ALTER TABLE`. **Mots réservés MySQL interdits** comme identifiants (`MysqlCompatibilityTest` : `start`, `end`, `groups`, `rank`, `range`, `order`, `condition`, `function`, `key`, `read`, `write`, `release`, `usage`, `system`, `current_value` au lieu de `last_value`, etc.). Aucun index sur TEXT/JSON.
- **Dépendances de production** : nikic/fast-route, nyholm/psr7(+server), php-di, monolog, vlucas/phpdotenv, spomky-labs/otphp, dompdf, chillerlan/php-qrcode. Outils : PHPUnit 10.5, PHPStan niveau 8 (sans baseline), PHP-CS-Fixer.

Design de référence (24 maquettes HTML) : `C:\Users\YCXL3291\Downloads\scholaris-html\scholaris-html` (Fondations.html donne les jetons). ## 10. Pièges connus
- Windows : `sed`/`node -e` avec antislashs et guillemets cassent les noms de classes PHP ; préférer l'outil d'édition de fichiers. Fins de ligne CRLF dans une partie du dépôt.
- Plusieurs agents en parallèle : dossiers exclusifs, jamais de réécriture ni de remplacement global d'un fichier partagé, relire juste avant d'éditer. Limites de quota d'API : les agents sont coupés ; les reprendre par message avec « audite l'état réel puis termine ». Les agents qui lisent trop de documents avant d'écrire décrochent : leur demander d'avancer par petits fichiers.
- Ne pas ajouter une permission ou un rôle dans une migration existante : créer une migration nouvelle préfixée par la date.
- Les modèles de messages de plateforme sont des données (`database/migrations/*message_templates*.sql`) ; la liste blanche des variables est `Messaging\Domain\TemplateRenderer::ALLOWED`.
- Git : branche `feat/rewrite-php-laravel` (publiée sur GitHub, jamais `main`) ; l'ancienne application NestJS est dans `archive/nestjs-nextjs`.
