# Réutilisation du socle par l'application Primaire et demandes de changement

Date : 2026-10-13. Modèle : `specs/002-application-ipes/socle-reuse-A.md`. Analyse en lecture seule du code réel. **Légende** : C = couvert, P = partiel, N = à créer ; PS = demande de changement du socle (« Primary Socle »), faite par l'agent propriétaire du module concerné, jamais par un agent Primary.

## 0. Constats transverses
1. **Règle d'architecture** : `Apps/Primary` n'utilise que les `Contracts/` du socle (`tests/Architecture/StandardsTest`) et ne lit aucune table d'un autre module (`NoForeignTableReadTest`). Les écrans du primaire appellent directement les routes du socle pour tout ce qui est C (personnes, inscriptions, frais, notes, présences, documents) : Primary n'ajoute des routes que pour ses données propres (`/primary/...`).
2. **Contrats d'écriture déjà livrés pour Higher et réutilisables** : `Organisation\Contracts\StructureWriter`, `AuthorizationRegistry`, `EnrolmentGuard`, `Assessment\Contracts\CurriculumCatalog`, `RuleStrategy`, `RuleScopeLineage`, `DeliberationGuard`, `Billing\Contracts\InvoiceIssuer`, `PaymentRequester`, `Documents\Contracts\DocumentIssuer`, `IssuanceGuard`, `Scheduling\Contracts\TimetableWriter`, `Staff\Contracts\AssignmentWriter`, `Platform\Contracts\ApplicationAccess`, `ApplicationManifest`.
3. **Points d'extension par clé de liste du conteneur** (découverts par `getKnownEntryNames()`, jamais par liaison unique, car `definitions.php` est fusionné par `array_merge`) : `platform.applications.primary`, `billing.fee_kinds.primary`, `portals.sections.primary`, `portals.grading_todo.primary`, `assessment.rule_strategies.primary`, `assessment.rule_scopes.primary`, `assessment.deliberation_guards.primary`, `documents.issuance_guards.primary`, `reporting.indicators.primary`, `reporting.dashboards.primary`, `reporting.todo.primary`, `integrations.export_types.primary`, `organisation.closure.checks.primary`, `organisation.closure.promotion.primary`, `privacy.tenant_data_source.primary`, `privacy.subject_data_source.primary`, `console.command.<nom>` ; enregistrements `EnrolmentGuards::PREFIX` et `EnrollmentNumberProvider::PREFIX` si besoin.
4. **Mécanismes Higher à recopier** (pas à partager : chaque application a les siens, dans son dossier) : `Support/WriteGate`, `Support/GatedAction`, `Support/HigherRoutes` → `PrimaryRoutes`, `Support/Perimeter` + `Policies/ScopeResolver` + `Support/ScopedBySchool` → `ScopedByClass` (périmètre section/niveau/classe), `Policies/RoleMatrix`, `HigherApplication` → `PrimaryApplication`. Un factorisation commune dans `src/Core` n'est **pas** demandée (fichier partagé, risque de collision avec IPES) ; à envisager quand trois applications existeront.
5. **SQL** : préfixe `pri_`, ULID `CHAR(26)`, dates `VARCHAR(32)`, montants XAF entiers, pas de clé étrangère ni d'AUTO_INCREMENT, une colonne par `ALTER TABLE`, aucun mot réservé (`rank`, `order`, `groups`, `range`, `condition`, `key`, `start`, `end`… : utiliser `rank_in_class`, `sort_order`, `class_ref`, `starts_on`, `ends_on`).

## 3. Ordre et regroupement
- **Tour a** (agents propriétaires, en parallèle) : W0P-1 Organisation + Attendance (PS1a, PS3, PS8 si Could retenu) ; W0P-2 Assessment (PS1b, PS2, PS4, PS5, PS9 si retenu).
- **Tour b** : W0P-3 squelette Primary + données partagées (PS6, PS7).
- Toutes les demandes sont **rétrocompatibles** (défauts = comportement actuel) : les 5130 tests existants restent verts ; chaque agent ajoute ses tests dans `tests/**/<Module>/`.
